Scenario 01 · Missing Data
Handling Missing Values in Housing Price Prediction
Dataset had missing entries for key features — number of bedrooms and square footage — in a house price prediction model.
⚡ APPROACH
Assess extent & pattern of missingness first, then choose between row removal or imputation based on proportion of missing values.
🔧 TECHNIQUES
Mean/median for numeric; mode or predictive imputation for categorical; regression imputation for large datasets.
💬 Key Insight from Bot Feedback
Start with simple baseline imputation before advancing to predictive models. Understanding why data is missing matters just as much as how to fill it — non-random missingness introduces systematic bias.
🐾
Scenario 02 · Class Imbalance
Addressing Imbalanced Classes in Animal Image Classification
Dataset had far more images of cats and dogs than birds or reptiles, risking a model biased toward predicting majority classes.
⚡ APPROACH
Combine resampling with class weighting. Replace accuracy with precision, recall, and F1-score as primary evaluation metrics.
🔧 TECHNIQUES
Data augmentation (flip, rotate, brightness); undersampling majority; class weighting in loss function; SMOTE for synthetic minority samples.
💬 Key Insight from Bot Feedback
No single fix is enough — layer oversampling, class weighting, and better metrics together. Aggressive oversampling without augmentation risks overfitting on repeated minority samples.
🔒
Scenario 03 · Data Privacy & Ethics
Privacy, Fairness & Ethics in ML Model Development
Building an ML model on personal user data raises questions of consent, minimization, bias monitoring, and regulatory compliance throughout the full development lifecycle.
⚡ APPROACH
Transparency & informed consent from day one; collect only necessary data; encrypt and anonymize PII; conduct regular fairness audits across groups.
🔧 SAFEGUARDS
Regulatory compliance (GDPR-style); pseudonymization; human oversight layer; diverse review teams to surface bias that technical audits miss.
💬 Key Insight from Bot Feedback
Responsible AI is continuous, not a checklist. Simplified consent language and visual explanations improve genuine user understanding. Diverse review teams surface issues that pure technical auditing cannot.
