Introduction

Pretrained weights reduce the work of starting a new model, but the right checkpoint depends on the task, available compute, and how a reviewer will verify a prediction. Explainability helps identify whether a model relies on relevant evidence, especially when its benchmark score conceals errors on inputs that matter to users.

Methodology and classification

I grouped the models by input and prediction task. BERT-base and DistilBERT form a teacher–student comparison for extractive question answering, MobileNetV2 and EfficientNet-B0 form a matched image classification comparison, and the original TabPFN represents pretrained tabular classification. TabPFN belongs in the tabular group even though its architecture is a transformer. It was pretrained on synthetic tasks and conditions on labeled rows at inference. I used parameter count as a portable size indicator and kept each benchmark metric and timing unit attached to its domain. A domain-first matrix allows direct comparisons where the tasks align and keeps the measurements that answer different questions in view.

  • Language. SQuAD 1.1 development F1 measures token overlap and exact match (EM) requires a fully correct span. Timing is a full STS-B inference pass at CPU batch size one. These timings are proxies for deployment planning and use a different task from SQuAD (Sanh et al., 2019, Tables 2–3).
  • Vision. Top-1 is the percentage of ImageNet-1K images with the correct highest-ranked label. Timing is per frame on the iPhone 12 Neural Engine using CoreML (Li et al., 2022, Table 1).
  • Tabular. One-vs-one ROC AUC measures class separation. Values average 18 numerical OpenML-CC18 datasets. Time includes the full fit-and-predict workflow for a split with 32 permutations and pretrained weights already loaded. Parameter count is rounded from the checkpoint count reported in the inference-dynamics study (Hollmann et al., 2023, Table 1; Is One Layer Enough?, Table 1).

Analysis and recommendations

Language · Document question answering

DistilBERT uses 40% fewer parameters and finishes the reported CPU suite about 39% sooner, with a 2.7-point drop in SQuAD F1. Start with DistilBERT for an internal FAQ on a CPU budget. Start with BERT-base when incorrect answer spans carry a higher review cost and local testing confirms a meaningful gain. Return each span with its source sentence, then remove supporting evidence and check whether confidence drops. Include unanswerable questions in local testing to validate abstention.

Vision · Edge camera and inspection

EfficientNet-B0 gains 5.3 percentage points of top-1 accuracy at 1.4 ms more NPU time per frame. Start with MobileNetV2 for a tight camera pipeline and EfficientNet-B0 when missed defects are costlier and the device meets its latency budget. Compare defect recall, test lighting and background shifts, and mask highlighted regions to check whether Grad-CAM highlights correspond to influential image areas.

Tabular · Small numerical datasets

Prototype TabPFN for low-volume equipment fault classification with mostly numerical inputs. Its aggregate ROC AUC of 0.934 is close to AutoGluon’s 0.930 in the same study. The reported CPU time illustrates the cost of using 32 permutations. Benchmark a simpler logistic regression or boosted-tree baseline on the same split, compare calibration, and use grouped feature perturbations when sensor readings are correlated. Validate performance separately on missing or categorical inputs.

Conclusion

Shortlist by task, use comparable benchmarks to identify candidates, and approve deployment only after checking local quality, p95 end-to-end latency, peak memory, and explanation stability. Claims about evidence from spans, heatmaps, and feature attributions should be checked by perturbing inputs and observing how predictions change.

Reflection on learning

Putting speed in a single column exposed the hardest classification decision. A full CPU inference pass, one mobile frame, and an in-context prediction over a dataset all describe runtime, but each answers a different operational question. Keeping the workload in each cell made the comparison more honest and made me ask which measurement I would need before selecting a model.

This connects to the course discussion of transfer learning and validation. Distillation can preserve much of a larger model’s benchmark performance with fewer weights, while TabPFN shows that reuse can happen through labeled examples at inference. The vision pair also brought back the problem of visual shortcuts from model evaluation. In a future project I would set the acceptance criteria before reading leaderboard results, then test explanations on failure cases and use those findings to decide whether to change the model, improve the data, or route uncertain predictions for review.
