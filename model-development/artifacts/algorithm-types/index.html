A visual framework for comparing ten machine learning algorithms and model families by learning approach, domain, and purpose.

A practical field guide

How models learn and what they do

Learning style describes the training signal. Domain describes the data or application. Task describes the result. These are different dimensions, not competing categories.

01

Learn from labeled examples

Supervised · Predict known targets.

Linear Regression · Decision Tree · Random Forest · Gradient Boosting · SVM · CNN classifier

02

Find structure without labels

Unsupervised · Discover patterns.

K-means groups examples. PCA compresses features. Neither directly learns fruit names.

03

Create targets from the data

Self-supervised · Learn representations or generation.

Transformers predict tokens. Diffusion models learn denoising. Later training may use labels or conditioning.

Read the labels carefully: CNN and Transformer describe architectures, not fixed learning styles. Here, CNN refers to supervised image classification. Self-supervision is often grouped under unsupervised learning because external task labels are not needed. Text-conditioned generation adds paired text information.

Connections that guide model selection

One tree → many trees
Decision Tree is the interpretable starting point. Random Forest combines randomized trees; Gradient Boosting builds a sequence of corrections.

Groups ≠ components
K-means assigns cluster membership. PCA creates fewer continuous features; it does not assign classes or clusters.

Understanding ↔ generation
Transformer representations support classification and generation with different objectives. Diffusion models generate through denoising, rather than next-token prediction.

About this artifact

Introduction and description

This guide introduces common algorithm choices across tabular data, computer vision, natural language processing, and generative AI. It combines a learning-style map, ten concise profiles, and a domain comparison matrix so learners can compare methods without confusing a task with its training approach. Examples illustrate potential uses; they are not claims of models implemented or evaluated here.

Objective

Explain how ten algorithms and model families work, classify their representative learning approaches, and connect them to practical applications. The intended audience is students and software practitioners beginning model selection.

Process and classification rationale

I organized the framework along three axes. First, I identified whether the selected training example uses external labels, discovers structure without labels, or creates its own targets. Second, I mapped each method to representative domains. Third, I identified whether its output is a prediction, group, representation, or newly generated content. I checked the distinctions against official documentation and original research.

I kept architectures separate from learning styles in the explanations: a CNN classifier is supervised in this example, while a Transformer can be pretrained with self-supervision and then fine-tuned with labeled data. Unconditional diffusion learns from noise-corrupted data without external class labels; caption-conditioned variants incorporate paired information. Domain tags overlap intentionally because one algorithm can serve several applications. This avoids presenting generative AI and NLP as mutually exclusive branches.

Tools and technologies used

HTML, CSS, JavaScript, SVG, GitHub, and GitHub Pages provide the framework, domain filtering, downloadable visual, version control, and portfolio presentation. ChatGPT assisted with content drafting and implementation. Technical sources are listed below; this artifact is a reference framework rather than an executable ML experiment.

Value proposition

The guide helps a learner start with the problem, available training signal, and desired output before selecting an algorithm. It makes the reasoning behind a shortlist visible rather than encouraging selection by model name alone.

Unique value

The learning map and domain matrix combine a conceptual overview with concrete examples. Explicit treatment of self-supervision explains why modern generative systems do not fit neatly into a single permanent supervised or unsupervised label.

Relevance

For Model Development, this artifact supports the early decisions that precede training and evaluation. For software teams, it provides an accessible starting point for discussing requirements, data preparation, and tradeoffs with colleagues.
